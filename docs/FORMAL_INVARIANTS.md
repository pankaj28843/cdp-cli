# Formal Browser Workflow Invariants

These invariants define the safety and liveness rules for cdp-cli browser workflows. They are intentionally executable: each row names the owning code, existing coverage, and the next check to add when the invariant changes.

## Headed self-heal verification contract

The headed repair state is intentionally finite:

| Property | Contract |
| --- | --- |
| Healthy fast path | A running headed runtime with a ready RPC socket and successful `Target.getTargets` returns `state=healthy`, `action=none`, and performs no Chrome activation, preference repair, or new daemon hold. |
| Repair safety | An unhealthy runtime has at most one `headed-remote-debugging-repair` owner. Its lease is 20 seconds, and an expired owner cannot update or remove a replacement lock. |
| Repair liveness | Within that lease, repair either proves `cdp_available` after the exact macOS approval action or returns structured `permission_pending`/connection evidence. |
| Counterexample trace | A live healthy cron tick spawning another headed hold; a 21-second repair; or an expired old owner deleting a replacement lock must be rejected. |
| Checker and trust boundary | No Dafny/Verus/TLA+/Z3 checker is installed in this repository, so the executable Go contract tests and live headed proof are a verified downgrade, not a theorem-prover claim. They trust the OS process table, Chrome AX/Quartz behavior, and the Go runtime. |

The finite-state contract is guarded by `internal/daemon/lock_test.go` and the
headed keepalive tests. The live proof must be rerun after changes to daemon
lifecycle, macOS accessibility, or lock ownership.

cdp --help
